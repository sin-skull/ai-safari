# ai Safari

`sin-skull/ai` のコードと履歴を複製した、iPhone 17 Safari向けの改修版です。元の開発とは別に進めます。

- 固定した複製元: [UPSTREAM.json](UPSTREAM.json)
- 改修方針と保存先: [docs/SAFARI_PLAN.md](docs/SAFARI_PLAN.md)
- 最新ロードマップ: [docs/ROADMAP.md](docs/ROADMAP.md)。自然言語会話の安定後に、コード生成・修正 → Webアプリ開発へ進みます。音声・操作も会話の基盤が完成してから取り組みます。
- 公開URL: https://sin-skull.github.io/ai-safari/
- 新しい会話画面: `index.html`。スマホ用 Qwen3 0.6B Q4 / CPU と PC用 Qwen3 0.6B Q4 / WebGPU を切り替えできます。
- 記憶の整理と既存形式のバックアップ: `memory.html`。この画面では旧モデルを起動しません。
- 実機確認と使い方: [docs/SAFARI_TEST.md](docs/SAFARI_TEST.md)
- **iPhone 17 Safariでの安定性は実機未検証です。音声入出力はまだ実装していません。**

## 0.15.2: 準備が切れても、送信でつながる

画面を離れてメモリを解放したあと・停止したあと・エラーのあとでも、送信するとその場で準備し直して答えます。一時的な失敗なら、準備を1回だけやり直します（モデル未保存・オフライン・別タブで使用中は、やり直さず理由を表示）。準備できているはずなのに計算が失敗したとき（Safari が裏で計算用の worker を止めた場合など）も、文字が出る前なら1回だけつなぎ直して答え直します。つなぎ直しは診断の記録に残ります（本文は残しません）。

## 0.15.1: 「会話を準備」を送信ボタンに統合

送信するだけで、必要ならモデルを準備してから答えます（初回はダウンロード）。準備に失敗したときは、入力した文章を残します。メニューの「先にモデルを準備する（任意）」は、送る前に読み込んでおきたいときだけ使います。強制終了のあとも、自動では再実行せず、次に送信したときに準備します。

## 0.15.0: 端末の情報・訂正・話題の切り替え・複数の依頼

実際の会話の書き出しを見て、モデルの前にアプリが決めることを直しました（`js/dialog.mjs`、テスト `tests/dialog.test.mjs`・`tests/dialog-browser.cjs`）。**自由会話の品質そのもの（モデルの選び直し）は未解決**で、候補を追加して評価を待っています。

1. **時刻・日付・通信状態はアプリが直接答える。**「今何時？」は端末の時計、「今オンライン？」はアプリの通信設定と端末の接続状態で答えます。モデルの準備は不要で、オフラインでも答えます。「オンラインとは？」のような意味の質問は、これまでどおり辞書へ回します。
2. **誤った答えを引きずらない。**「違う」「意味わからない」などの否定には、モデルを使わず取り消しを伝えます。直前のモデルの答えに印を付け、以後の文脈には渡しません（画面では薄く表示）。「正しくは佐藤です」のような訂正と、「私の名前は田中です」のような利用者自身についての発言は、最優先の事実として指示文に入れます。
   - 渡す履歴の選び方も変えました。用語の意味を聞く質問には、過去の答えを渡しません（小さなモデルが前の答えの言い回しを写すため）。続きの質問（「それって？」）と相づちには直前の1往復だけ、話題が変わったら内容の重なる往復だけを渡します。端末の情報・辞書・フレーズの答えは、モデルの文脈に入れません。
3. **複数の依頼を分ける。**「いわゆるの意味と、扇風機のおすすめ」は、用語の意味を辞書から答え、おすすめは使う場所・予算・重視することを聞き返します。条件が届いたら、商品名やメーカー名は保存資料にあるものだけを使い、無ければ選び方を答えるよう指示してモデルに渡します。内蔵辞書に日常語5語（いわゆる・扇風機・時間・状態・無駄）を足しました。
4. **日本語の会話の候補を追加（評価中）。** モデルの選択に、日本語で学習・調整された Sarashina2.2 0.5B／1B、LFM2.5 1.2B JP、TinySwallow 1.5B を追加しました。品質の評価場面にも、用語の説明・雑談・話題の切り替え・訂正を足しました。**どの候補も、この環境では実モデルで評価できていません**（Hugging Face からモデルを取得できないため）。評価の手順は [docs/QUALITY_EVALUATION.md](docs/QUALITY_EVALUATION.md) の末尾を参照してください。

## 0.14.1: 自然言語の品質を最優先に

新機能より、自然に会話が成立することを優先します。[実モデルの比較結果と再現手順](docs/QUALITY_EVALUATION.md)を追加しました。現行モデルの復唱や人物の取り違えは、ブラウザ以外でも再現しています。別の小型モデル・日本語の指示・1.7Bのモデルも比較しましたが、自由会話の合格には至っていません。今回、標準モデルは変更していません。

`tests/quality-eval.cjs` は7場面・11発言を実モデルで評価し、回答と時間を保存します。ダウンロード済みのモデルと独立したブラウザ、またはPC内の検証用llama-serverを使用します。外部AIサービスは使いません。公開した評価例は架空の会話で、個人の会話履歴は含みません。

不具合修正: `おかえり？と聞かれたら、「ただいま」と答えて` のように読点を含む明示的な指示も、フレーズとして保存できるようにしました。この修正は自由会話の生成品質改善とは別です。

## 0.14.0 の会話画面

会話中心のレイアウトに変更しました。上部のタブで会話を切り替え、PCでは左側の一覧からも選べます。「＋」は既存履歴を消さず新しい会話を作成します。各会話は履歴と入力途中の文章を別々に保存し、生成の文脈にもその会話の履歴だけを渡します。辞書・フレーズなど、利用者が明示的に保存した記憶は共通です。50会話まで、各40往復を保存します。生成中は混在を防ぐため切り替えを無効にし、「止める」の後に切り替えられます。

「☰ メニュー」にアプリ更新、モデル、通信、口調・長さ、辞書、バックアップをまとめました。会話の名前変更・個別削除・書き出しもここで行えます。従来の履歴は初回に1つの会話へ移行し、アップデートで消去しません。旧形式の記録は移行した会話を削除するまで復旧用に残します。全会話の書き出しは新形式（`ai-safari-chats`）で、現在その一括読み込みには未対応です。

「オンライン」を「外部取得を許可」と表示し、会話生成が引き続き端末内の同じモデルであることを明示しています。この更新に生成モデルの変更は含みません。

検証: `tests/chat-tabs-browser.cjs` で旧履歴の移行、会話・下書きの分離、キーボード切り替え、生成中の切り替え防止、停止、名前変更、削除、メニューのフォーカスを確認します。生成部分は制御可能なテスト用モデルであり、実モデルの回答品質を示す試験ではありません。

会話欄でも `おかえりと言われたら「ただいま」って答えて` の形式でフレーズを教えられます。明示的な指示を端末に保存し、次の一致する呼びかけには保存した返答だけを返します。

通信モードを切り替えられます。オフラインでは外部検索・未取得モデルのダウンロード・更新確認を止めます。オンラインでも回答生成は端末内のままで、外部AIサービスは使いません。Wikipedia検索は検索ボタンを押した言葉だけを送り、結果は利用者が選んで辞書と参考資料に保存します。ブラウザ自身によるページ取得やService Workerの更新確認とは別の、アプリの機能の設定です。

「辞書・参考資料」に手書きの基礎17語を初期登録します（総合国語辞典ではありません）。用語の追加とJSON取り込みに対応し、初期化で利用者の定義を上書きしません。JSONは `[{"term":"用語","definition":"説明"}]` または既存バックアップの `terms` 配列を読み込めます。同じ用語の取り込みは現在の定義を残します。用語の意味を聞くと生成を介さず定義を返し、自由な会話では辞書と保存資料を文脈に加えます。実際に渡した抜粋を回答の「参照した内容」に表示します。

意味検索は任意です。同じモデル・版・次元で作った保存ベクトルと元の文章を使います。検索時の質問もベクトル化が必要なので、e5-small（初回約120MB）を読み込みます。回答用モデルを解放してから検索モデルを使い、解放後に回答用モデルを再開します。索引のない場合や検索に失敗した場合は言葉の一致に戻ります。「索引化」は保存文章を対象とし、辞書は用語の一致で参照します。iPhoneのメモリと待ち時間の負担が増えるため、初期状態は無効です。

**自由な会話の日本語品質は未解決です。** CPUで実モデルを使い、「猫を飼う準備」「仕事で疲れた」への回答を旧設定とQwenの推奨生成設定で比較しましたが、どちらも不自然な回答がありました。設定変更による改善は確認できなかったため採用していません。再現用 `tests/quality-bench.cjs` はモデルを約397MB取得します。辞書検索・フレーズ返答の成功を、生成品質の改善とは扱いません。

「フレーズを教える」で呼びかけと返答を端末に保存できます。登録したフレーズは、オフラインでもモデルの準備なしでそのまま返答します。検索やAIの推測ではなく、教えた記憶からの返答だと表示します。編集・削除でき、削除した初期例は復活しません。未登録のフレーズは自動取得しません。

「口調」（標準・親しみやすい・丁寧）と「回答の長さ」（短め・標準・詳しく）を選べます。次の回答から反映し、選択は端末に保存します。モデルの再取得・再読み込みは不要です。PCの「詳しく」は最大768トークン、スマホは最大320トークンまで生成可能にし、入力履歴の予算も合わせて調整します。文字数の保証ではなく、小型モデルが指示を守らない場合もあります。

ホーム画面から起動しても、画面上部の「アプリを更新」で最新版を取得して再起動できます。履歴・記憶・保存モデル・入力中の文章を保持します。更新にはインターネット接続が必要です。

スマホ用CPUモードはWasm32互換版を使います。PC上のWebKit試験で、Memory64の対応判定を通っても実行時に停止する問題を確認したためです。再現用の自動試験は `tests/mobile-webkit.cjs`、結果と限界は [Safari確認手順](docs/SAFARI_TEST.md) に記録しています。

初回は「会話を準備」でモデルと実行用ファイルを保存します。保存後は通信なしでモデルを開きます。会話は端末内で生成し、会話文を外部APIへ送りません。画面を閉じた後も自動でモデルを読み込まず、準備ボタンで再開します。

スマホ用は1スレッドのCPU、コンテキスト2048、バッチ32、同時実行1件。PC用はWebGPU、コンテキスト4096です。切り替え時には前のWorkerの終了を待ちます。初期設定の検索は既存の文字索引を使用します。

会話履歴は直近40往復を端末に保存し、モデルには容量に収まる直近最大6往復だけを渡します。途中停止した回答は次の会話の文脈から除きます。特に残したい利用者の発言は「この発言を記憶に保存」で従来の文章ストアに追加できます。

最小のLFM2 350Mも動作確認用に残します。Qwen3は公式モデルのUnsloth製Q4_K_M変換（約397MB）。スマホ/PCモードでは同じ保存モデルを使い、実行方法と文脈の上限を変えます。思考モードを無効にして待ち時間を抑えます。

モデルとコードは固定バージョン。モデルはHugging Faceから初回取得、実行部品はこのサイトから取得します。保存はブラウザの管理下なので、Safariのサイトデータを消すと再取得が必要です。小型モデルは日本語の言い回しや事実を誤ることがあり、会話品質は継続して調整します。

モデル出典: [Qwen3公式説明](https://huggingface.co/Qwen/Qwen3-0.6B-GGUF)、[使用するUnsloth量子化版](https://huggingface.co/unsloth/Qwen3-0.6B-GGUF)。モデルの版はコード内のコミットIDに固定しています。

## 複製元の設計・記録

以下は複製元から継承した設計です。旧モデルの動作記録は新会話画面の検証結果ではありません。


オフラインでも使える、自作のAIアシスタント。

**頭脳は共通、記憶は各自。** 検索で知識を蓄え、オフラインでは蓄えた知識だけで答える。蓄積したデータは各自の端末の中にだけ置く。

- ロードマップ: [docs/ROADMAP.md](docs/ROADMAP.md)
- データ設計: [docs/DATA_DESIGN.md](docs/DATA_DESIGN.md)

## 設計原則

1. 記憶は端末内だけに置く。サーバーに個人データを溜めない。
2. 共有するのは読み取り専用の部品（アプリ本体、埋め込みモデル、百科事典パック）だけ。
3. 何を残すかは常に自分で決める。保存前に確認し、後から消せる。
4. 単語は重複なしの辞書に統合し、文章は出典付きで丸ごと保存して1件ずつ削除できる。
5. 評価はユーザーの操作（👍/👎）を主にし、言葉の感情分析は補助にする。
6. 検索は成長の源。答えられなかった質問は未回答キューに残し、次のオンライン時に調べる。
7. 見た目は手作り感を優先し、テンプレ的なAI臭さを避ける。

## 状態

フェーズ2（オフライン化）と、フェーズ3のA・B（Wikipedia検索・未回答キュー）まで完了。フェーズ4（意味検索）は実装済みで、実モデルでの精度も測定した（言い換えの質問で、キーワード 41% → 意味検索 97%）。機内モードでの動作も実機で確認した。フェーズ5（回答生成）は実装済みで、小さな言語モデルが保存した文章を読んで根拠つきで答える（実機での確認はこれから）。モデルは端末に保存され、メニューからいつでも消せる。フェーズ6（成長の仕組み）も実装済み：👍/👎・ピン留め・「ありがとう」などの言葉が検索の順位に反映され、「整理」タブで低評価・未使用・古い知識を確認つきで消したり、Wikipediaから取り直したりできる。単語と文章の保存・検索、Wikipediaで調べる、👍/👎、オフラインモード、書き出し／読み込みが使える。進め方は [docs/ROADMAP.md](docs/ROADMAP.md) を参照。方針は「すべてスマホの中で完結」。次は、フェーズ7（調べるを意味で選び直す・大量データの取り込み・情報源の追加）、そのあとフェーズ8（会話）に進む。

## 使い方

- 「AI = 人工知能」と送ると覚える（「単語：意味」でもよい）
- 「AIとは？」「AI」と送ると、覚えている意味を答える
- 「AIは人工知能」のような文は、確認してから覚える
- 同じ語を違う意味で教えると、「上書き／追記／今のまま」を選べる
- 長い文章（2文以上など）を送ると、確認のうえ文章として保存できる。聞くと、保存した文章からも探す
- 知らない語は、ボタンを押したときだけWikipediaで調べて覚えられる（出典も保存）
- 左上のメニューから、単語・文章を探したり消したりできる（消すときは2回押す）
- 答えられなかった質問は「未回答」に残る。オンラインのときにまとめてWikipediaで調べ、残すものを自分で選べる（自動では保存しない）
- メニュー下の「意味検索」を有効にすると（約120MB・初回のみ）、言い換えた質問でも保存した文章が見つかる
- ヘッダーの「オンライン／オフライン」を押すと切り替わる。オフラインモード中は外部に一切通信しない
- メニュー下の「書き出す／読み込む」でバックアップ（JSON）。端末の都合で消えることがあるので、ときどき取る

### iPhone で使うとき

1. 初回は Safari で公開URL（https）を開く。ここで本体が端末に保存される
2. 共有ボタン →「ホーム画面に追加」。以後はホーム画面のアイコンから開く（機内モードでも開ける）
3. Safari のタブのまま長く使わないと、保存データが消されることがある。ホーム画面に追加すると防ぎやすい

## 動かし方

`index.html` をブラウザで開くだけで動く（サーバー不要）。データはそのブラウザの IndexedDB に保存される。オフライン起動（Service Worker）と「ホーム画面に追加」は、https（または localhost）で開いたときだけ働く。

## テスト

ロジックの回帰テストは `pnpm install --frozen-lockfile` → `pnpm test` で実行できます。Node版はIndexedDBを模擬し、ブラウザ専用のOPFS/WorkerテストとiPhone実機の動作確認は含みません。

`tests/test.html` をブラウザで開くと、回帰テストが走る。
